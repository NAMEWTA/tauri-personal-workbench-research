## 1. 产品定义与范围

今日、任务、日历共享同一个 Task 实体、任务 ID、状态、截止时间和修改入口。今日按关注范围组织任务，任务页展示清单，日历按截止日期组织清单。

每条 Todo 只需要一个可选的截止时间。填写后自动出现在对应日期；清除后回到“未设置截止时间”。彻底移除“安排到日历”、开始时间、结束时间、持续时长、日历拉伸和旧排程条件。

档案现有的类型、基础/扩展字段和表格方向继续保留。本轮只验证任务关联档案、跳转及共享布局没有回归。

## 3. 截止时间与三视图规则

### 3.1 一个截止信息

UI 只保留“截止时间”一个入口，允许三种状态：

1. 未设置：任务留在清单，日历不为它虚构日期。
2. 仅日期：例如 9 月 6 日，不强迫填写小时。
3. 日期和时刻：例如 9 月 6 日 16:45。

日期选择器提供今天、明天、下周、清除日期，以及“添加时间”。再次打开时准确还原已有值。全日精度通过“只设日期”表达，删除旧的“全天任务”排程开关。

建议 API 用一个 deadline 联合对象表达以上状态，避免日期与时间范围形成两套事实：

```ts
type Deadline =
  | null
  | { kind: 'date'; date: string; timezone: string }
  | { kind: 'datetime'; at: string; timezone: string }
```

日期分支的 date 是 YYYY-MM-DD；datetime 的 at 是规范化的 UTC RFC3339 时间，timezone 是用于输入和重复规则的 IANA 时区。数据库为这两个互斥分支设置 CHECK，不接受混合载荷，也不使用 endsAt 兜底读取截止时间。

统一规则：

- 指定时刻的未完成任务：当前时刻超过截止时刻才算逾期。
- 仅日期的未完成任务：截止日期的次日开始才算逾期，不在当天 00:00 提前标红。
- 已完成任务始终不标记为逾期。
- 日切、休眠唤醒和切回应用时重新计算“今天”，范围使用本地日历边界，不能简单加 24 小时。
- 工作区当前展示时区统一应用于三个视图；date 类型保持选定日期，datetime 按展示时区映射日期；异于展示时区的截止信息在编辑器中明确注明。
- 夏令时不存在的本地时间要求重新选择；重叠时间必须确定偏移，不能默默改写。

### 3.2 视图与筛选

| 视图 | 默认内容 | 完成行为 |
| --- | --- | --- |
| 今日 | 逾期未完成、今日截止未完成、今日已完成；三个分组不重复计数 | 本行立即勾选和划线，随后进入展开的“今日已完成”；保留撤销入口 |
| 任务 | 全部任务，可按状态、截止范围、是否有截止时间筛选 | “全部”确实含已完成；“待办”只含 todo/doing；筛选产生隐藏时给出操作反馈 |
| 日历 | 当前月/周/日范围内所有有截止信息的任务，默认包含已完成 | 完成任务保留在原截止日，标题划线；不因完成时间搬到另一日 |

“今日已完成”按 completedAt 取当天完成的记录，因此一条昨天截止、今天完成的任务，会同时出现在今日完成分组和昨天的日历。这是同一条记录的两种观察角度，不能复制任务补齐两个视图。

无截止时间的任务不自动进入“今日待办”。如果它在今天完成，可以进入今日已完成分组。所有入口读取同一条任务详情。

### 3.3 排序

按照本次用户要求，默认同一天内截止时刻降序：18:00 → 16:45 → 09:00。提供“晚截止在前 / 早截止在前”两个清楚的选项，保存为工作区偏好。

- 月/周列按真实日期从左至右排列；每一天内部遵循上述时间排序。
- 只有日期没有具体时刻的任务单独放在该日“未指定时刻”区，不能伪装成 00:00 或 23:59。
- 同一时刻使用 createdAt、id 作为稳定的次级排序键，更新标题不会使任务随机跳位。
- 默认排序不被优先级或日历布局算法偷偷覆盖。
- 日历完成任务保持该日原时间位置；今日已完成分组按完成时间展示，属于明确标注的历史分组。
- 数据量大时同样必须覆盖整个已选日期范围，不能只加载默认第一页后在客户端假装完整。

## 4. 界面与操作

### 4.1 月、周、日

- 月视图：保留熟悉的月份网格。每项显示“完成圆圈 + 截止时刻 + 标题”；标题最多两行，窄格保留省略和完整内容入口。
- 周视图：七列日期，每列是按截止时间排序的紧凑 Todo 清单，移除 00:00–24:00 时间刻度。
- 日视图：该日期的完整任务清单，复用 TaskRow，不另写一套日程表。
- 默认为周一开始；“今天”用日期圆点和轻背景强调，避免整日高饱和色块。
- 同日任务很多时展示“还有 N 项”，点击进入该日完整列表/浮层；不是静默裁掉其余任务。
- 工具栏统一为：日期导航、月份/周范围、月/周/日切换、完成项显示、添加任务；宽度不足时自然换行。
- 取消默认展开的“未排程”侧栏；需要时通过“未设置截止时间（N）”打开可关闭的小清单。空清单不占一整列。
- 保留当前 FullCalendar 6.1.19 的日期网格能力，使用 dayGridMonth/dayGridWeek 与自定义任务渲染；本轮不顺带升级主版本。
- 移除 timegrid 依赖和没有消费者的时间范围代码。日历适配层可以向库传递 start 来放置日期，但它只由 deadline 派生，不进入业务 API 或数据库。
- 显式启用严格排序；必要时使用服务端有序结果的展示索引，避免日历为了紧凑布局重新安排顺序。

### 4.2 任务行与完成反馈

- 主内容点击打开任务详情；手型指针覆盖标题和相应点击区域；hover 使用轻背景，当前选中行使用稳定的选中底色。
- 左侧圆圈只负责完成/取消完成，点击不会同时展开详情。
- 标题完成态使用删除线、勾选图标和清楚的文字色，不把整行降到难以阅读的透明度。
- 右侧截止时间可直接打开日期选择器；更多按钮提供改期、清除日期、删除等动作。
- 快捷按钮在 hover 或键盘 focus-within 时出现，触控环境始终可找到。
- Tab 可抵达完成、详情、日期、更多按钮；Enter/Space 执行动作，Esc 关闭浮层并返回原控件。
- 点击任务主体默认 pointer；拖动只在独立拖动区域使用 grab/grabbing，避免整个任务行都看起来在拖拽。
- 删除进入回收站并提供撤销；完成反馈不抢焦点；失败恢复该行原值并提示重试，不把其他行都标成失败。
- 详情编辑期间的外部状态变化不得通过组件重新挂载丢失未保存草稿。

### 4.3 新建与详情

统一 QuickTaskForm 与详情编辑模型，不再为日历维护第二个新建表单。

| 新建入口 | 默认截止信息 | 提交后 |
| --- | --- | --- |
| 今日快速添加 | 今天，仅日期 | 显示在今日与当天日历；焦点留在快速添加框，支持连续录入 |
| 任务页快速添加 | 未设置 | 显示在任务清单；不强制打开详情 |
| 日历选定日期的 + | 所选日期，仅日期 | 自动出现在所选日期，可直接补充时刻 |
| 日历顶部添加 | 当前选中日期，无选择则今天 | 同一个编辑器，日期上下文可见 |

任务详情默认只展开标题、截止时间、备注、关联档案。优先级、重复、提醒放在紧凑的属性区，低频信息折叠；默认不突出预计分钟和底层 parentId。

顶部只显示一次可编辑任务标题，取消“检查器 / 任务详情 / 同名标题”三层重复。关闭按钮和未保存提示始终可见。详情表单保留清晰的保存/取消；只有产生修改时显示底部固定操作栏。快捷完成和日期浮层用明确的即时操作语义，成功后可撤销。

日历拖动只改截止日期，保留原来的具体时刻；只有日期的任务继续保持日期精度。已完成任务不接受拖动。失败回滚日历位置、Todo 清单、详情和计数。删除 eventResize、范围选择与默认一小时长度。

### 4.4 布局与纸张主题

- 主内容、详情之间使用内容宽度约束；详情默认约 360px。
- 当打开详情会使日历内容窄于可用网格宽度时，详情切换为侧向抽屉，不再强行挤压七列。
- 未选择任务时不默认占用空详情栏。
- 窄窗口周视图可以切为按天纵向清单；用户能看见视图变化，所有日期与任务仍可到达。
- 移除 `.calendar-surface` 的无条件 680px 最小宽度约束；处理全局 grid 的最小列宽，验证窗口缩放与详情展开组合。
- 页面、网格与抽屉的滚动责任明确，避免页面和表格同时出现横向滚动条。

纸张主题建议降低橙黄色覆盖面：

| 角色 | 初始色值 | 用途 |
| --- | --- | --- |
| 背景 | #F7F3EA | 安静的暖纸色 |
| 内容面 | #FFFCF5 | 提升正文和输入区辨识度 |
| 正文 | #322D27 | 深墨色 |
| 次要文字 | #776C60 | 日期和说明，保持可读性 |
| 分隔线 | #E4DBCD | 更轻的 1px 边界 |
| 主操作 | #99632E | 少量用于添加、当前选中等强调 |

这些是原型起点，不是已通过视觉验收的最终 token。正文以 14px 为基准，日期说明至少 12px；任务行约 48–56px，图标保持 16–18px，交互热区扩大到 32px 以上。对比度须实测，普通文字目标至少 4.5:1，控件可识别边界至少 3:1。

如增加纸纹，使用极低强度 CSS 纹理并只应用于大背景；不影响正文、表格、输入框的辨识。动效控制在 120–180ms，支持 reduced-motion；完成动画不导致连续点击时目标突然移动。

## 5. 重复、提醒与一致性

截图中每天重复的“办税”，6 日已完成与 7 日待办可以是两个不同轮次，必须通过完成样式和重复标记看得出来。

必需的行为：

1. 完成本次时保留本次记录，并且只生成一个下一轮。只为已有的真实任务轮次生成日历条目，视图切换不得产生记录。
2. 系列 ID 与轮次标识可唯一定位任务；完成状态变更和下一轮创建在同一事务内，设置系列/轮次唯一约束。
3. 快速双击、并发请求、网络重试不会重复创建；重新打开已完成任务再完成，也不会多生一轮。
4. 撤销完成：恢复本次状态；下一轮尚未被用户修改时同步撤回；若已经修改则保留下一轮并清楚说明，不删除用户内容。再次完成复用已存在的下一轮。
5. 下一轮基于本轮截止日期/时刻递推，保留当地钟表时刻。逾期完成默认生成紧接本轮的下一次，不跳过或补造多条历史任务；需要跳到未来由用户明确改期。
6. 月末默认取目标月份最后一天，并保留系列原始日号：1 月 31 日 → 2 月最后一天 → 3 月 31 日。
7. 重复任务编辑本轮与后续需要不同作用域。默认改本轮，修改重复设置时明确给出对后续的影响，已完成历史不被批量改写。
8. 提醒使用相对截止时间的规则，如“截止时 / 提前 10 分钟 / 提前 1 小时”，不能复制上一轮的绝对时间戳。
9. 无具体时刻时，提醒必须另选清楚的提醒时刻；完成、删除和清除截止信息会使相应提醒失效或要求调整。
10. 本轮不承诺应用退出后后台提醒；若产品以后要求关闭应用仍通知，应作为原生系统调度能力另行验收。

## 6. 前后端实施边界

### 6.1 后端与契约

- OpenAPI 是唯一契约，继续使用 /api/v3；更新 Task、TaskCreate、TaskPatch 与过滤参数，生成 Go/TypeScript 代码。
- 使用部分更新请求，只有用户修改的字段参与写入；区分未传字段与显式 null 清除，不再从过期详情拼整条 TaskInput 覆盖服务端数据。
- 增加任务 revision 和服务端冲突检查，过期修改返回可处理的冲突；客户端保留草稿并提供重新加载/重试。
- 后端统一截止时间验证、日期范围、逾期、完成过滤和排序逻辑。Dashboard 调用同一任务查询服务，仅做聚合，不再另写 endsAt 逾期判断。
- 日历范围使用 [from, to) 的半开区间，补齐月首月末可见日期；同一套参数得到一致任务 ID 集合。
- 移除 startsAt、endsAt、allDay、includeUnscheduled 等旧排程契约、索引、校验、适配和测试夹具。未知旧字段明确拒绝，不默默接受。
- 任务变更、下一轮生成、提醒调整与活动记录形成可回滚事务。
- 将 paper 加入真实持久化约束，并同时验证新建数据库、当前数据库转换候选路径和备份恢复路径。

### 6.2 前端复用

保留 TodayPage、TasksPage、CalendarPage 作为入口。共用以下模块，避免每个页面复制过滤、日期和状态逻辑：

- deadline：时间输入/显示、精度和日切边界适配。
- task-presentation：状态、完成标题、时刻展示、优先级。
- TaskRow、TaskCompletionControl、TaskDeadlinePicker、TaskEditor：主要操作与可访问性。
- task view queries：状态/日期/范围/排序统一 key，包含 workspaceId、展示时区及当前日信息。
- task mutations：取消过期查询、仅更新对应任务、失败恢复、成功校准受影响列表。

今日、任务、日历、详情和档案关联任务在同一个任务 mutation 之后得到一致结果。任务变更只刷新依赖任务的查询，避免目前每次刷新全部档案、附件和活动列表。

所有页面查询消费 AbortSignal；切换工作区取消旧请求并隔离缓存。视图切换保留所选日期、筛选、滚动和排序偏好，先恢复偏好再查询，避免视觉跳动。

## 7. 现有数据策略：待用户选择

此前用户要求不保留旧兼容路径；本次截图显示正在使用 0.2.12 的真实任务。已在对话中询问是否允许仅对当前版本进行一次升级转换，答复前不执行任何转换或重置。

无论最终选择哪条路径：

- 不自动删除、清空、覆盖用户原工作区和备份。
- 不把启动切换到一个空工作区作为成功恢复原数据。
- 不在运行时保留 startsAt/endsAt 回退读取或两套任务模型。
- 应用版本、API 版本、数据库迁移版本、备份格式版本分别定义和校验，不能因为都含有“2”就认定兼容。
- 当前 migrations.CurrentVersion 实际为 1；历史上存在其他 schema 2，新的结构不能仅凭数字接收这些历史文件。需验证所属结构与来源，给出安全诊断。

候选 A：用户允许保留当前数据的一次性转换。只接受已确认的 0.2.12 结构，先生成可验证副本和转换报告，在副本事务中转换并核对数量、任务关联、档案/附件与校验；成功后才允许切换。默认已有 dueOn → 日期精度 deadline；仅有旧排程 → endsAt 转 deadline；两者同时存在时保留显式 dueOn，不擅自把排程终点理解为用户截止意图。原时间范围保留在转换报告，需人工关注的记录逐项列出。转换工具不进入产品运行时；旧格式输入继续拒绝。

候选 B：继续完全无转换的新基线。旧工作区原样保留；明确提示其不能在新模型下打开，新建工作区与旧数据位置都可识别。没有用户明确选择，不能把已有档案迁入或删除旧目录。

这项决定影响实施票据与发布说明；其他 UI、统一查询和验收条款不依赖它，可以先定稿。

## 9. 必验场景

### 9.1 用户直接关心的闭环

1. 在任务页创建“办税”，只设置今天 16:45：今日、清单、日历出现同一个 ID 和截止时间。
2. 在日历点击完成：当天条目显示勾选和标题删除线；任务列表同步；今日完成计数更新；任务详情状态一致。
3. 每天重复的办税完成后：今天保留已完成，明天只出现一个待办轮次，时刻保持 16:45。
4. 鼠标经过任务标题和可点击区域出现手型；hover、focus、selected 可区分；完成控件不会打开详情。
5. 同一天创建 09:00、18:00、16:45 三条任务：月/周/日各自该日顺序严格为 18:00、16:45、09:00；刷新后保持。
6. 只设置日期，任务显示在该日的“未指定时刻”；清除截止信息后从日历消失，仍在任务清单。
7. 从月/周拖到明天：只改变截止日期，三个入口同步；模拟 API 失败时全部回滚。
8. 今日快速新增默认今天，日历新增继承点击日期；没有任何“安排到日历”或时间范围步骤。

### 9.2 边界与可靠性

- 完成、撤销、再次完成、并发完成及超时重试：无重复下一轮；未保存草稿不被覆盖。
- 月末、跨年、闰年、UTC 日期边界、日切、夏令时：期限、逾期和重复轮次一致。
- 关联档案任务的完成/改期同步到档案详情；档案基本功能和字段展示不回归。
- 改主题为 paper → API/数据库保存成功 → 退出 → 重启后仍为 paper → 切另一工作区不串主题。
- 同一天 30/50 条任务、超长标题、中英文混合、emoji、无截止任务、空结果、请求失败、慢请求。
- 1280×800、1440×900、960×640、800×700，加 1024×768；100% 与 125% 缩放，开/关详情以及完整七列可见性。
- 键盘新建、Enter/Space 完成、Esc 关闭、焦点返回、无嵌套交互控件、可访问名称正确。
- 自动化验证实际 computed style 的 line-through/cursor、状态和任务 ID；截图验证格子遮挡、工具栏、浮层、重复标题和密度。

### 9.3 测试与发布

- pnpm check；Go test、race、vet；Rust fmt、clippy、test。
- 前端 Vitest 默认 worker 与单 worker；OpenAPI lint、代码生成后无漂移；文档链接、版本与旧排程字段守护扫描。
- 拆分 Todo/Calendar 场景测试，不能只依赖一条长 smoke 或既有绿色结果。
- Windows 原生 WebView2 下跑与浏览器相同的关键闭环，覆盖工作区切换、偏好保存、数据库隔离、重启和退出。
- 本次安装包与 portable 安装/解压、启动、任务操作、关闭、无残留、卸载；下载当前 Release 资产核验 checksum 后再次运行。
- macOS 当前提交 native evidence、bundle、DMG 与签名检查；旧 artifacts 不替代新产物。
- 不靠不断增加超时、跳过失败断言或强制杀进程让测试表面通过；遇到失败保留截图、日志和具体复现，区分产品缺陷与测试驱动问题。
